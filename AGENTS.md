# AGENTS.md

`agent-notes` is a Go CLI and MCP server that keeps shared knowledge notes as Markdown files
in a repository's `.notes/` folder. Details for contributors: [docs/development.md](docs/development.md).

## Layout

- `cmd/agent-notes`: `main`, wires the OS into `cli.Run`
- `internal/cli`: argument parsing, commands, output
- `internal/note`: note model, frontmatter format, slugs and tags
- `internal/store`: note files and notes directory resolution
- `internal/search`: tag filtering and keyword ranking
- `internal/notejson`: JSON shape shared by the CLI and the MCP server
- `internal/mcpserver`: MCP tools over a store
- `internal/memory`: Claude Code memory file parsing
- `internal/version`: version reporting
- `integrations/claude-code`: Claude Code skill
- `scripts/`: `release.sh`, `changelog.sh`, `dist.sh`, tested by `*_test.sh`
- `docs/`: user and contributor docs

## Before every commit

```sh
go test -race ./...
go vet ./...
gofmt -l .                  # must print nothing
scripts/changelog_test.sh   # when touching scripts/
scripts/release_test.sh     # when touching scripts/
scripts/dist_test.sh        # when touching scripts/ or docs/
```

## Test-driven development (required)

1. Write a failing test first. Run it and see it fail for the expected reason.
2. Write the minimal code to make it pass.
3. Refactor with the tests green.

- No production code without a test that needed it.
- A bug fix starts with a regression test that reproduces the bug.
- Test through public APIs: `cli.Run` with `t.TempDir()` and an injected `cli.Env`
  (env vars, clock); shell scripts through their `*_test.sh` in throwaway git repos.

## Conventional Commits (required)

Format: `type(scope): description`, imperative, lowercase start, no trailing period, for
example `fix(store): keep file permissions on update`.

- Types: `feat`, `fix`, `perf`, `refactor`, `test`, `docs`, `build`, `ci`, `style`,
  `chore`, `revert`.
- In CHANGELOG.md: `feat` (Added), `fix` (Fixed), `perf` (Changed) and breaking changes.
  The others are left out.
- Scopes: `note`, `store`, `search`, `cli`, `mcp`, `memory`, `changelog`, `release`.
- Breaking change: `feat(cli)!: ...` or a `BREAKING CHANGE:` footer.
- One logical change per commit; every commit passes the checks above.

## Rules

- `CHANGELOG.md` and `VERSION` are generated by `scripts/release.sh`. Never edit them by hand.
- Never run `scripts/release.sh` with a bump type, tag or push unless the user asks.
- No new dependencies without a justification in the commit message; prefer the standard
  library.
- Keep `docs/` in sync with behavior: update the relevant page in the same commit.
- Match the existing style: concise, idiomatic Go, sparse comments, table-driven tests,
  `t.TempDir()` for files.
